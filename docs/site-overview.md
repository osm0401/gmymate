# GAINMUSCLE 사이트 구조

최종 정리: 2026-08-14

## 화면

| 파일 | 역할 |
|---|---|
| `index.html` | 로그인, 회원가입 이동, 샘플 데이터 체험 |
| `onboarding.html` | 키, 나이, 몸무게, 목표, 운동 경력 입력 |
| `main.html` | 홈, 달력, 운동 기록, AI, 루틴, 음악, 내 정보 |
| `offline.html` | 네트워크가 없을 때 표시하는 PWA 안내 |
| `privacy.html` | 개인정보 처리 안내 |

## 핵심 흐름

1. 사용자는 로그인하거나 샘플 데이터로 바로 체험합니다.
2. 기록 화면에서 운동을 여러 개 추가하고 순서를 바꾸거나 같은 부위 운동으로 교체합니다.
3. 세트를 선택해 무게와 횟수를 조절하고 완료하면 휴식 타이머가 시작됩니다.
4. 완료 기록은 기기에 먼저 저장되며 로그인 상태에서는 MySQL과 동기화됩니다.
5. 홈에서 회복 점수와 최근 7일 운동량, 연속 운동일, 종목별 성장을 확인합니다.
6. AI 버튼은 모든 주요 화면의 하단 중앙에서 열리며 PHP 서버를 통해 Gemini를 호출합니다.

## 프런트엔드 모듈

| 경로 | 책임 |
|---|---|
| `src/core/` | 데이터, 저장, 인증, 동기화, 분석 등 DOM과 분리된 로직 |
| `src/features/` | 로그인, 기록, 회복, 분석, AI 등 화면 기능 |
| `src/styles/` | 기능별 반응형 스타일 |
| `src/app.js` | 인증 후 각 기능을 연결하는 진입점 |

## 서버

| 경로 | 역할 |
|---|---|
| `api/session.php` | 세션, JSON 응답, 요청 크기 제한, 로그인 속도 제한 |
| `api/signup.php`, `api/login.php` | 회원가입과 로그인 |
| `api/sync.php` | 사용자별 운동 데이터 동기화 |
| `api/delete-account.php` | 비밀번호 재확인 후 계정과 데이터 삭제 |
| `api/gemini.php` | 로그인 사용자용 Gemini 프록시와 호출 제한 |
| `api/music/` | 음악 서비스 연결과 플레이리스트 API |
| `api/schema.sql` | MySQL 8 테이블과 외래 키 |

DB 비밀번호와 Gemini 키는 브라우저 코드에 넣지 않습니다. 실제 값은 Git에서 제외된 서버 설정 파일에만 저장합니다.

## 저장 방식

- 운동 중인 데이터는 `localStorage`에 즉시 저장해 새로고침이나 일시적인 통신 오류에도 유지합니다.
- 로그인 계정은 `api/sync.php`를 통해 서버의 `user_data`와 동기화합니다.
- 서비스 워커는 정적 파일만 캐시하고 로그인, AI, 사용자 API 응답은 캐시하지 않습니다.
- 여러 기기에서 동시에 수정하면 마지막 동기화 값이 우선되는 단순 정책입니다.
