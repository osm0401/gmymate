# GAINMUSCLE 포트폴리오 요약

최종 정리: 2026-08-14

## 프로젝트 목표

GAINMUSCLE은 헬스장에서 휴대전화 한 손으로 빠르게 운동을 기록하도록 만든 모바일 우선 웹앱입니다. 초보자도 설명 없이 사용할 수 있는 흐름과 통신이 끊겨도 기록을 잃지 않는 구조를 목표로 했습니다.

## 구현 기능

| 영역 | 기능 |
|---|---|
| 계정 | 회원가입, 로그인 유지, 로그아웃, 비밀번호 확인 후 계정 삭제 |
| 운동 기록 | 검색과 다중 추가, 순서 변경, 운동 교체, 세트 추가·삭제, 무게·횟수 조절, 완료 체크 |
| 운동 보조 | 이전 기록 불러오기, 예상 1RM, PR, 슈퍼세트, 워밍업 세트, 휴식 타이머 |
| 루틴 | 추천 루틴, 나만의 루틴, 운동별 목표 무게·횟수·세트 설정 |
| 회복 | 수면, 에너지, 근육 뻐근함을 이용한 오늘의 회복 점수 |
| 분석 | 최근 7일 세션·볼륨, 연속 운동일, 종목별 최고 무게 변화 |
| 가이드 | 모든 운동의 목표 부위, 수행 순서, 주의점 |
| AI | Gemini 기반 운동·영양·회복 코칭, 일반 대화와 간단한 계산, 응답 중지 |
| 편의성 | 달력, 인바디 기록, 운동 알림, 접근성 설정, 음악 플레이리스트 |
| 설치·오프라인 | PWA 설치, 정적 화면과 로컬 기록의 오프라인 사용, 재연결 후 동기화 |
| 시연 | 계정을 만들지 않아도 전체 흐름을 보는 샘플 데이터 모드 |

## 해결한 기술 문제

1. 브라우저가 MySQL에 직접 연결하지 않도록 PHP API와 PDO prepared statement를 사용했습니다.
2. 실제 DB의 `users.id BIGINT`에 맞춰 모든 사용자 외래 키 타입을 통일했습니다.
3. 운동 중 데이터는 기기에 먼저 저장해 통신 장애에도 입력을 잃지 않게 했습니다.
4. 로그인 실패 횟수, JSON 요청 크기, AI 호출 횟수와 입력 길이를 서버에서 제한했습니다.
5. 서비스 워커가 API나 개인 응답을 캐시하지 않도록 정적 파일과 서버 요청을 분리했습니다.
6. 분석 계산과 가이드 데이터를 DOM에서 분리해 Node 단위 테스트로 검증했습니다.
7. 320px와 390px 화면에서 하단 AI 버튼, 타이머, 채팅 입력창이 잘리지 않도록 자동화 테스트를 추가했습니다.

## 검증 범위

- Node 단위·계약 테스트 97개
- Playwright 모바일 E2E 3개 흐름
- JavaScript 문법, HTML 참조, 배포 목록, 보안 설정 계약 검사
- PHP CLI가 없는 로컬 환경에서는 PHP 문법 검사를 건너뛰며 실제 호스팅에서 최종 확인이 필요함

## 포트폴리오에서 강조할 점

- 화면만 만든 것이 아니라 로그인, DB, 오프라인, AI, 보안, 테스트, FTP 배포까지 연결했습니다.
- 실제 사용 중 발견한 모바일 잘림과 데이터 저장 문제를 재현하고 자동 테스트로 다시 생기지 않게 했습니다.
- AI는 핵심 운동 기록 기능과 분리해 API 장애가 나도 기록 기능은 계속 사용할 수 있습니다.
- 샘플 모드로 평가자가 개인정보 입력 없이 완성된 사용 흐름을 확인할 수 있습니다.
