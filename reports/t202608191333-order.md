## 리서치 근거 (검색으로 확인한 사실 + 왜 이 방식을 택했는지)

- 저장소에는 이미 회복 기록 정규화 모듈과 동기화 경로가 있다. `gmymateRecoveryCheckins`와 `gmymateProfile` 모두 `src/core/sync.js`의 동기화 대상이며 `api/sync.php`가 계정별 JSON 블롭으로 저장한다. 따라서 서버 리소스를 추가하지 않고 기존 객체를 확장하는 것이 D-B와 가장 잘 맞는다.
- 운동의 기존 `category`는 `등`, `가슴`, `하체` 같은 운동 분류이므로 어깨·허리·무릎 부담을 판정하기에 부족하다. 운동별 명시적 `warningAreas`를 두고 하나의 교집합 함수로 모든 화면을 판정한다.
- Fitbod는 어깨·허리·무릎 같은 빠른 선택, 운동 제외·대체, 회복 처리 기능을 제공하지만 특정 우선 운동이 제한 설정을 우회할 수 있다고 명시한다. 이번 MVP는 자동 제외 대신 모든 운동 진입 경로에 동일 경고를 적용해 우회 경로를 줄인다. [Fitbod Injuries and Limitations](https://help.fitbod.me/hc/en-us/articles/37629269518103-Injuries-and-Limitations)
- Freeletics는 부위 제한을 근육통용으로 설명하며 실제 부상에는 의료 조언을 받도록 안내한다. 따라서 기능을 “안전한 운동 추천”으로 표현하지 않고 사용자 확인용 경고로 한정한다. [Freeletics FAQ](https://www.freeletics.com/en/blog/posts/the-freeletics-faq/)
- NHS는 부상 시 해당 운동을 멈추고, 통증 악화·심한 부기·체중 부하 불가 등의 상황에는 의료 도움을 받도록 안내한다. 회복 점수가 높더라도 통증이 기록되면 기존의 무조건적인 운동 허용 문구를 안전 문구로 대체한다. [NHS Sprains and strains](https://www.nhs.uk/conditions/sprains-and-strains/)
- 통증·부상 위치는 건강정보로 볼 가능성이 높다. 개인정보 보호법 제23조는 건강정보를 민감정보로 분류하고 별도 동의와 안전조치를 요구하므로, 개인정보처리방침 수정만으로 끝내지 않고 최초 저장 전 별도 동의와 철회·삭제 경로를 둔다. 최종 적법성은 법무 검토 대상으로 남긴다. [개인정보 보호법 제23조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1027416043)
- 다중 선택은 새 UI 라이브러리 없이 네이티브 체크박스와 `FormData.getAll()`로 구현할 수 있다. 해당 API는 주요 브라우저에서 널리 지원된다. [MDN FormData.getAll](https://developer.mozilla.org/en-US/docs/Web/API/FormData/getAll), [MDN checkbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/checkbox)
- 경고는 색상만으로 전달하면 안 된다. 텍스트·아이콘·접근 가능한 이름을 함께 사용한다. [WCAG 2.2 Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)
- 2026-08-19 기준 `@playwright/test` 최신 안정판은 `1.62.1`이며 현재 lockfile도 같은 버전이다. Playwright `<1.55.1`에 영향을 준 CVE-2025-59288의 대상이 아니므로 이 PR에서 의존성 변경은 하지 않는다. [npm @playwright/test](https://www.npmjs.com/package/%40playwright/test), [Playwright releases](https://github.com/Microsoft/playwright/releases), [NVD CVE-2025-59288](https://nvd.nist.gov/vuln/detail/CVE-2025-59288)
- 현재 단위 테스트 기준선은 97개 모두 통과한다. 신규 테스트는 이 기준을 깨뜨리지 않아야 한다.

- [ ] `api/**`, DB 스키마, npm 의존성 변경이 없다.
- [ ] 기존 97개 단위 테스트와 신규 테스트가 모두 통과하며 관련 순수 로직의 lines/branches/functions 커버리지가 각각 80% 이상이다.
- [ ] 모바일 Chromium E2E와 오프라인 재접속 흐름이 통과한다.

## 예상 리스크

- 운동별 부위 매핑은 의학적 안전을 보장하지 않는다. 승인되지 않은 매핑은 병합 금지이며 테스트는 구조적 정확성만 보장한다.
- `other` 일반 경고는 범위가 넓어 경고 피로를 유발할 수 있다. 상세 부위나 진단명 입력은 별도 기능으로 다룬다.
- `user_data`는 whole-blob last-write-wins 방식이므로 오래된 기기의 저장이 최신 부상 프로필을 덮어쓸 수 있다. 이번 PR에서는 동기화 충돌 해결을 추가하지 않는다.
- 통증·부상 정보는 평문 localStorage에 있고 같은 페이지에서 AdFit 외부 스크립트가 실행된다. 외부 전송 여부가 검증되지 않으면 광고 격리 또는 저장 방식 개선을 별도 보안 PR로 만들고 운영 배포를 보류한다.
- `sync.php`에는 필드별 스키마 검증이 없으므로 모든 신뢰 경계 검증을 클라이언트 정규화 함수에서 반복해야 한다. 서버는 이번 PR에서 불투명 JSON 저장소로 유지한다.
- 별도 동의 기록을 JSON 프로필에 저장하는 방식이 법적 증빙으로 충분한지는 확정되지 않았다. 법무 검토에서 부족하다고 판단되면 별도 BE 동의 이력 PR을 선행한다.
- 현재 전체 프로필 수정 링크는 가입 흐름을 재사용하는 기존 문제가 있다. 이 PR에서는 해당 흐름을 고치지 않으며, 신규 부상 프로필 편집은 내 정보 화면에서 독립적으로 제공한다.
