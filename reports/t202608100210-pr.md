# 나만의 루틴 추가 — 작업 지시서

## 목표

로그인 사용자가 오늘 구성한 운동 목록에 이름을 붙여 저장하고, 루틴 탭에서 다시 시작하거나 삭제할 수 있게 한다.

- 담당: `[FE]` Claude, 리뷰·테스트: Gemini
- 브랜치: `fe/custom-routine-mvp`
- 저장 단위: `{ id, name, exerciseIds }`
- 한도: 사용자당 30개, 루틴당 운동 1~12개
- 백엔드: 기존 `api/sync.php`의 사용자별 JSON 동기화를 재사용하며 신규 API·테이블을 만들지 않는다.
- 비범위: 세트·중량·횟수·휴식시간 저장, 루틴 편집·공유·즐겨찾기·주간 일정·AI 추천·사용자 정의 운동

현재 체크아웃을 구현 기준으로 삼는다. 단, 배포 기준이 로컬 `main`의 `src/features/routines.js` 포함 상태라면 기능이 이미 있으므로 신규 구현을 중단하고 검증·테스트 작업으로 전환한다. 크게 분기된 `5007997` 커밋을 통째로 cherry-pick하지 않는다.

## 리서치 근거 (검색으로 확인한 사실 + 왜 이 방식을 택했는지)

- 현재 저장 폼과 내 루틴 영역은 `main.html`에 있고, 렌더·삭제·시작 코드도 일부 존재한다. 빠진 것은 폼 제출 처리, 최초 렌더, `gmymateCustomRoutines` 동기화 연결이다. 따라서 새 화면보다 이 연결부를 완성하는 것이 가장 작은 PR이다.
- Strong은 현재 또는 완료한 운동을 템플릿으로 저장하고 재사용한다. 이는 gmymate의 기존 “오늘 구성한 운동을 루틴으로 저장” 흐름과 일치한다. [Strong 템플릿 안내](https://help.strongapp.io/article/105-about-templates)
- Hevy는 루틴을 재사용 가능한 계획, 워크아웃을 실제 수행 기록으로 구분하고 루틴에서 새 워크아웃을 시작한다. 따라서 루틴 시작 후의 기록 변경은 원본 루틴을 수정하지 않아야 한다. [Hevy 루틴과 워크아웃](https://help.hevyapp.com/hc/en-us/articles/33703513582871-Workouts-vs-Routines-in-Hevy-What-They-Mean-and-How-to-Use-Them)
- Fitbod도 현재 운동을 이름 있는 Saved Workout으로 저장한다. 과거 기록 저장과 자동 중량 조정은 성숙 기능이므로 후속 PR로 남긴다. [Fitbod Save a Workout](https://help.fitbod.me/hc/en-us/articles/6259258835863-Save-a-Workout)
- 저장소에는 `package.json`이나 `composer.json`이 없다. 바닐라 ES Modules, PHP/PDO, Web Storage만 사용하므로 신규 라이브러리는 필요 없다.
- `localStorage`는 동기식이며 용량 초과 시 `QuotaExceededError`, 정책 제한 시 `SecurityError`가 발생할 수 있다. 작은 루틴 목록에는 충분하지만 저장 실패를 처리해야 한다. [MDN Web Storage](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API), [MDN 저장소 한도](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)
- `innerHTML`은 deprecated가 아니지만 XSS 주입 지점이다. 루틴명은 `textContent`로 넣거나 기존 `escapeHtml()`을 모든 텍스트·속성에 적용해야 한다. 별도 sanitizer 패키지는 도입하지 않는다. [MDN innerHTML 보안 경고](https://developer.mozilla.org/en-US/docs/Web/API/Element/innerHTML), [OWASP DOM XSS 예방](https://cheatsheetseries.owasp.org/cheatsheets/DOM_based_XSS_Prevention_Cheat_Sheet.html)
- 2026-08-10 기준 PHP 최신 안정 패치는 보안 릴리스인 8.5.9다. 이번 PR은 PHP를 변경하지 않지만 운영 환경은 지원 중인 PHP 브랜치의 최신 보안 패치인지 확인한다. [PHP 8.5.9 릴리스](https://www.php.net/releases/8_5_9.php), [PHP 지원 버전](https://www.php.net/supported-versions.php)
